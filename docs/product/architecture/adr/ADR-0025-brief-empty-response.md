# ADR-0025: 브리핑 빈 결과는 404 가 아니라 200 + `{ brief: null }`

- 상태: 채택 (2026-09-07)
- 관련: FR-AGENT-04, [ADR-0011](ADR-0011-agent-backend-db-access.md), Phase D3

## 맥락
`GET /api/brief/today` 는 오늘자 브리핑을 반환한다. 브리핑은 에이전트가 매일 아침
스케줄러로 생성하므로, 아직 실행 전이거나 실패한 시간대에는 오늘 행이 없다. 이 "정상적인
빈 상태"를 어떤 HTTP 형태로 표현할지 정해야 한다.

## 결정
오늘 행이 없으면 **200 OK** 와 함께 본문 `{ "brief": null }` 을 반환한다. 404 는 쓰지 않는다.

## 근거
- 빈 브리핑은 오류가 아니라 **예상된 일상 상태**다(아침 스케줄 전). 404 는 클라이언트에서
  에러 처리 경로를 타게 만들어 불필요한 에러 배너를 띄운다.
- 프런트 위젯은 `loaded && !brief` 로 "아직 없음" 을 자연스럽게 표현할 수 있다.
- 다른 조회 API(`/api/calendar/events`, `/api/sync/logs`)도 빈 결과를 200 + 빈 배열로 준다 —
  일관성.

## 대안
- **404 Not Found:** 리소스 부재의 정석이지만, 위 근거대로 위젯 UX 와 맞지 않는다.
- **204 No Content:** 본문이 없어 클라이언트가 JSON 파싱 분기를 따로 둬야 한다.

## 결과 / 트레이드오프
- 클라이언트는 `data.brief` 가 `null` 일 수 있음을 항상 가정해야 한다.
- AGENT.md·API_REFERENCE.md·UI_SPEC.md 의 기존 404 표기를 200/null 로 정정했다.
